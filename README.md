# AI-Assisted Software Engineering: Principles for Building Sustainable Systems with AI

> A working framework: observations and logical conclusions from hands-on experimentation with AI-assisted software development, still being tested as I keep observing.

AI has lowered the barrier to implementation without lowering the need for engineering. These principles are guide rails for directing AI's implementation capability toward sustainable engineering.

## What's here

- [**PRINCIPLES.md**](PRINCIPLES.md): the full document, 16 principles organized around four pillars.
- [**PLAYBOOK.md**](PLAYBOOK.md): how I work with AI agents, as short rules drawn from real projects.
- [**templates/**](templates): files to copy into your repo (AGENTS.md, handoffs, ADRs, STATUS and more).
- [**field-notes/**](field-notes): dated notes on how specific AI tools behave, kept apart from the rules because they go out of date.
- [**case-studies/**](case-studies): real project walkthroughs where the principles held up (or didn't).
- [**posts/**](posts): launch post, carousel, and follow-up writing.
- [**CHANGELOG.md**](CHANGELOG.md): version history of the framework.
- [**BACKLOG.md**](BACKLOG.md): what's next, and ideas not tested yet.
- [**AGENTS.md**](AGENTS.md): how AI assistants work on this repo, built from the template.

## The four pillars

1. **Think before you generate.**
2. **Generate responsibly.**
3. **Prove it works.**
4. **Build for the future.**

## Contributing

This framework is deliberately a working document. Some ideas will evolve, some might be wrong. If you're a practitioner with observations, open an issue or a PR. That's the point of doing this in public.
